# 如流聊天与任务

普通消息默认发送到绑定智能体的 Multica 聊天会话，连续对话保留上下文。
会话按机器人、绑定账号、工作区、私聊/群聊、发送人隔离，切换智能体会创建新会话。
群里继续要求 @ 机器人；访问控制沿用机器人允许名单。

- `/issue <内容>`：创建 issue，并将结果回复到当前会话。
- `帮我创建一个任务：<内容>`、`新建 issue：<内容>`：同上。
- `/new`：开始新对话，旧对话仍保留在网页版；不取消正在执行的请求。
- `/status`：查询当前聊天；没有聊天时查询本会话最近的 issue。
- `/status CBH-15`：查询指定 issue 的执行状态。群里仅返回发送者在该会话最近创建的任务。
- `/help`：查看用法。

模糊请求（例如“帮我优化性能”）、否定句、引用中的建单描述均按聊天处理。
自然语言建单采用明确的开头规则，不对模糊句子作模型猜测。
普通聊天直接传递用户消息，不附加固定的聊天模式提示词。建单分流由 Bridge 处理。
普通聊天可以执行工具，因此仍可能消耗运行时资源；Bridge 分流不是对智能体工具的服务器权限限制。

聊天图片通过附件 API 上传，引用消息保留现有解析结果。
会话及待回传的执行 ID 保存到 `state.json.chat-<scope>.json`（权限 0600），
Bridge 重启后继续等待已提交请求的回复。每轮按 task_id 匹配，不回传其他轮次的答案。
超时后可用 `/status` 或网页版查看。网络中断时发送结果可能不确定，不自动重发用户输入。
账号身份沿用机器人绑定的 Multica profile，聊天会出现在该账号的网页版中。

部署：加载 `deploy/env.sh` 后重启 Bridge，以继承 IM API 地址等部署配置。
聊天状态文件应与 `config.local.json`、`state.json` 一并纳入实例备份；不要提交 Git。
