# Deployed updates — 2026-10-15

This release collects the deployed conversation and UI improvements since the
previous published baseline. Deployment-specific URLs, credentials, invite
tokens, build outputs, logs and backups are not included.

## InfoFlow conversations

- Notify the bound conversation when an issue is bound or unbound.
- Mirror issue-page user comments and agent replies to their bound conversations,
  retaining sender attribution and delivery safeguards.
- Show the connected robot in private-binding UI and guide users when no robot
  is available.
- Handle `/help` and `/status` independently of task selection. Group status lists
  the current group's bound issues; private status includes authorized related
  issues and their binding state.
- Include task links in multi-task ambiguity prompts and show task titles and
  responsible agents in status results.
- Confirm successful robot/agent binding and start the management endpoint before
  slow robot gateway connections finish.
- Notify the signed-in operator after deleting a robot binding. Send with the
  captured robot identity after removal, without recreating its connection;
  notification failure does not undo deletion and is reported separately.

## Shared agent chats

- Use workspace membership and agent invocation permissions for chat access.
- Allow authorized non-owners to read and continue accessible conversations.
- Preserve per-message sender attribution, creator-only management actions and
  attachment/realtime permission checks.

## Navigation and sign-in

- Add collapsible common links for copying the mobile-control URL, model quality
  probing, quick-start material and official documentation.
- Open common links upwards without moving footer controls; remove the old help
  button.
- Keep the InfoFlow community link as a separate fixed button above statistics.
- Place quick-start and community links together, centered directly below the
  sign-in title. Preserve verification-bot guidance and input styling.
- Keep all deployment-specific addresses in the private build manifest and check
  that rebuilding preserves required configuration.

## Scope and verification

- The upstream submodule revision is unchanged.
- The staged user-owned runtime / runtime-decoupling work is explicitly excluded.
- Recent UI rollout passed 35 login tests and 15 overlay regression tests; the
  preceding combined UI rollout passed 41 login/sidebar tests. Browser checks
  confirmed link targets, centered layout, fixed footer positions and copying.
- Deployment backups and rollout evidence stay private. Publishing this release
  does not deploy code, migrate a database or restart any service or daemon.
- These are local/deployment verification results, not a claim that GitHub CI
  has run or passed for the publishing commit.
- Before publication, 101 focused Bridge tests were rerun after replacing a
  deployment address in test fixtures with a reserved example domain.
