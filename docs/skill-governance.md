# Skill 名称、创建者与来源更新

团队、工作区和个人 Skill 共用一个名称空间。名称比较前去掉首尾 Unicode 空白并转为小写；展示保留原大小写。名称查找和导入查重使用同一规则。数据库全局唯一索引保护所有写入路径，界面或 CLI 不能绕过。

历史重名保留全部记录。团队优先，其次工作区、个人；同级按创建时间、ID 排序。优先项保留原名，其他项使用 `-2`、`-3` 等后缀并跳过所有已占用名称。迁移只修改名称，原内容、创建者、范围、ID、文件和绑定不变。`team_mesh_skill_rename_audit` 留存旧名与新名；迁移可重复执行，回退只恢复尚未被用户改动的名称。外部脚本中写死的旧名称需自行调整，按 ID 的绑定不受影响。

只有创建者可以修改、删除、更新内容或调整范围；不要求创建者仍是来源工作区成员。工作区管理员没有额外管理权限。其他用户仍可按原有读取和智能体权限使用 Skill。

新建和导入遇到重名时默认拒绝，不自动生成副本。冲突信息展示名称、范围和创建者，不提供私有 Skill 的内容或管理权限。显式覆盖仍按原有创建者权限执行，并且目标必须处于原范围；跨范围覆盖被拒绝。已有的显式改名另存和跳过操作仍受全局约束。

列表和详情返回 `creator: {user_id, name, avatar_url}`，不依赖当前工作区成员列表，也不返回创建者邮箱。

`POST /api/skills/{id}/refresh` 保留无请求体的旧调用，并支持 `{"url":"<新的受支持地址>"}`。可更新原本没有来源的手动 Skill。地址沿用 URL 导入支持的来源及下载校验，成功后保存新来源并更新说明、正文和文件；平台名称、范围、创建者、ID 和绑定不变。失败不改数据。后续不传地址时使用已保存的新来源。

发布时先备份，在 API 暂停写入期间执行 556、557 两个迁移，验证索引有效和非名称数据不变后再启动新版 API、Web。已有运行继续使用已取得的上下文，后续执行使用新名称，不强制重启客户端 daemon。CLI 忽略大小写的名称查找需要使用配套新 CLI；旧 CLI 仍可使用准确名称或完整 ID。
